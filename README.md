## 项目定位

- **目标游玩体量**：每天 4–6 小时，约 1 个月完成一个主结局路线，完整内容约 80–100 小时。
- **技术栈**：TypeScript、Phaser 3、Vite，可选 Tauri 打包为桌面应用。
- **运行原则**：纯本地离线，运行时不包含任何 AI 模型或 API 调用。

## 操作（当前原型）

| 按键 | 作用 |
|---|---|
| WASD | 移动（地表、地牢） |
| E | 靠近 NPC：先接取其发布的任务，再按一次对话；靠近裂隙传送门：进入地牢；地牢商店房间：打开/关闭商店；结局面板：关闭 |
| Q | 打开/关闭任务日志；1–3 或点击选择追踪，B/N 翻页，V 查看全部目标与奖励 |
| I | 打开/关闭背包 |
| C | 打开/关闭装备面板；面板打开时数字键 1–6 依次切换主手、头部、胸甲、脚部、手部、项链的装备（循环：已有装备 → 卸下） |
| R | 打开/关闭阵营声望面板（五个阵营的档位） |
| G | 打开/关闭技能面板：B 切换武艺/奥术/生存分支，数字键 1–9 学习当前页的技能，N 翻页，X 重置当前分支（花费金币，返还技能点）。升级每级 +1 技能点；已学主动技能可再次点击装配，F 切换目标槽位。组合技在 4 秒内连续成功施放对应技能触发 |
| H / M | 使用治疗 / 魔力药剂（共享 8 秒冷却） |
| K | 地表/地牢手动存档；地牢移动、互动及战斗结算时自动保存 |
| T | 进入测试房间 |
| Shift / Space / J | 冲刺 / 闪避 / 按住自动追击并普攻（松开 J 停止追击，WASD 手动走位优先；闪避与冲刺消耗耐力） |
| 数字键 | 战斗中 1–4 施放技能（也可点击）；地牢中移动到相邻房间；对话中选择选项；关键抉择出现时选择；面板打开时：技能面板选择技能、装备面板切换槽位、地牢商店购买对应物品 |
| Tab / 点击怪物 | 战斗中循环切换 / 直接锁定目标；目标死亡后自动选择下一名存活敌人 |
| L | 离开地牢（已获得奖励和房间探索进度均保留） |

出生点附近有行旅商人（坐标 4,4），走近按 E 可交易，点击卡片或按 1–6 操作本页；N/P 翻页，V 切换买卖。面板可用 Esc 关闭；技能和装备面板支持点击操作。

标题菜单可以选择“新游戏”或“继续”。有活动地牢时直接恢复地牢检查点；战斗中刷新回到出战前。存档保存在浏览器本地存储中，保留上一份有效备份用于损坏恢复；清除站点数据会同时删除主档与备份。

地表视野随白天、黄昏、夜晚、天气变化；只有视野内的敌人刷新点会显示。区域门槛：裂隙核心、泥沼、沙丘需要对应阵营声望达到“友好”，否则不会算作抵达（会有提示）。

## 开发环境

环境要求：Node.js 20.19+ 或 22.12+（建议 Node.js 22 LTS）。

```bash
npm install            # 安装依赖
npm run dev            # 启动浏览器开发服务器（http://localhost:5173）
npm run typecheck      # TypeScript 类型检查
npm run validate:data  # 校验 data/ 中的 JSON 引用与字段
npm test               # 运行单元测试
npm run build          # 类型检查 + 生产构建，输出到 dist/
npm run preview        # 预览生产构建（http://localhost:4173）
npm run build:standalone  # 生成单文件版 dist-standalone/rift-chronicles.html（可直接双击打开，无需服务器）
```

**发布产物**：`dist/` 是网站式产物（入口 `index.html` 加 `assets/`，需要静态服务器，已使用相对路径）。
`dist-standalone/rift-chronicles.html` 是单文件版，内联了全部脚本，可以离线直接打开；运行时不发起任何网络请求。
桌面安装包（Tauri）尚未配置，计划在阶段 8 加入。

> 打包桌面应用（`npm run tauri build`）计划在阶段 8 加入。

**内存较小的机器**：如果 `npm run build` 被系统终止（Killed / OOM），可以用
`npx vite build` 配合 `sourcemap: false`（当前配置已默认关闭）。Phaser 体积较大，
构建时需要约 1.5 GB 可用内存。

克隆仓库前请先安装 Git LFS：

```bash
git lfs install
git clone git@github.com:Anjichen584/claude-haiku-5.5.git
```

本项目在开发期间使用 Claude Haiku 辅助编写代码。这只属于开发阶段的工程辅助，**游戏运行时不包含任何 AI 组件或 API 调用**。

### 沙箱开发预览

默认开发服务器仅绑定本机。需要 Arena/e2b 托管预览时运行 `SANDBOX_PREVIEW=1 npm run dev`，显式绑定 `0.0.0.0` 并仅额外放行 `.e2b.app` 主机名。不要将开发服务器用于正式发布。

优化实施与验证见 [可靠性和界面优化](docs/optimization-implementation.md)。

战斗接敌优化：遭遇战有短暂入场缓冲，敌人随后主动接近；按住 J 无需另按方向键即可接近并普攻。静止施放攻击型技能会辅助朝向最近敌人，但仍受射程、魔力与冷却限制。见 [战斗接敌优化](docs/combat-engagement.md)。

目标锁定、群怪间距和蓄力进度预警见 [战斗第二轮优化](docs/combat-targeting.md)。

战斗结算会显示经验、金币与背包净变化；N/P 翻阅详情，R 重试保存，松开 Space 后重新按下或点击返回。保存失败时请勿刷新。详见 [战斗结算优化](docs/combat-results.md)。

任务追踪会保存在旧格式兼容的存档中。NPC 头顶 `!` 表示可接任务，`?` 表示可交付，淡色圆点表示任务进行中；可交付时优先进入交付对话。接取和对话交付后自动保存，失败时请勿刷新，按 K 重试。详见 [任务探索闭环](docs/quest-journey.md)。

分阶段提交、远端备份标签与回退约定见 [维护与备份流程](docs/maintenance-workflow.md)。

新手前两章的营地首次补给、队长初见/回访与真实输入路线验证见 [新手路线修复记录](docs/early-route.md)。第二章靠近营地中心会一次性补足所需碎片；已完成章节的旧档不补发，旧档仍在第二章时可返营领取。

维护约定更新：按仓库所有者授权，后续验证通过后直接提交并推送 `main`，不再自动创建优化分支；重要版本保留备份标签。推送 `main` 会触发 CI 和现有 Pages 发布。
