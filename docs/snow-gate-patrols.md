# 雪门巡逻路线修复

## 第一阶段：可靠的第三章遭遇与生命周期

### 采样证据

种子 20261014，区块 x=-7..2、y=-8..0（90 个区块）自然生成 125 组遭遇，其中只有 5 只霜狼；聚落过滤还可能移除遭遇。这说明开局到雪门方向没有足够的可靠自然来源，不表示无限世界只有五只。

### 改动

- 雪门营地外增加三组固定剧情巡逻，每组两只霜狼，仅第三章 active 时可见、可触发、可追踪。属于明确的任务路线设计调整，不伪称旧世界本来就有这些敌人。
- 位置按雪门坐标和固定偏移确定，遇到交互区时稳定搜索；避开全部地点及 NPC 的交互范围，组间距至少 12 格；不移动原地图/NPC/玩家坐标。
- 使用独立 `snow-gate-patrol-*` 击败键和现有 defeated 存档字段，无版本迁移。未接任务前不能提前打掉；完成/失败后不再出现，旧 active 存档可正常遇到。
- 全部固定巡逻坐标可用于远距离指引；已击败或非 active 的巡逻不进入指引。依然优先最近的实际敌人来源。
- 不增加无条件回血、不注入药剂、不修改自然刷怪、掉落和战斗数值。

### 验证

532 项测试 / 46 文件，类型检查、数据校验、单文件构建、audit 0 漏洞。新增单元测试覆盖六只总量、稳定位置/顺序无关、交互区净空、章节门控、普通遭遇不受影响、v1 读档和击败键去重。

`early_route_e2e.py --snow` 完整通过：全新档真实 WASD/J/H/空格输入，三组新手狼、营地、支线、存档/回访后走到雪门外打完三组霜狼，完成第三章、存档刷新继续。六场实战，347.8 秒，无页面错误。只读场景状态来选择输入，没有传送、血量/物品/任务事件注入。自动闪避策略下六场结束时均为 100 HP，最后有六瓶治疗药剂；不能据此宣称普通玩家平衡或所有策略都如此，故本次没有再发额外药剂。

首次长路线跑完战斗/章节后在读档集合比较失败：存档会排序 defeated，现按集合内容比较；完整重跑通过。生命周期夹具随后暴露视野刷新会覆盖隐藏标记，已将章节门控与视野条件合并为同一个 visible 判定，避免先隐藏再被后续逻辑显示。

修复后的 `story_patrols_e2e.py` 通过：区块已加载时，前置章节隐藏且不触发；active 后无需重载可显现；完成后隐藏且不触发；重新构造 active 夹具会触发正确巡逻。这是状态/位置夹具，不是另一遍实走。混合目标 HUD、Q 跟踪、交付/读档/存储失败重试、24 章任务逻辑与结局、file:// 离线回归也通过。24 章回归仍不是实走通关。

## 第二阶段：旧档结算、防回归与可复核采样

补充旧 active 档已经发现雪门且只剩四次击杀的测试：已有 reach 从 visited 恢复，完成后只结算一次，读档再击杀不重发奖励，剩余巡逻全部失效。另测交互区占据默认位置时的稳定避让。最终 534 项测试 / 46 文件通过。

新增可复核命令：

```bash
node --import tsx scripts/audit-snow-route.ts
```

输出样本边界、自然遭遇数量、聚落过滤前后霜狼数量、每个来源的坐标以及剧情巡逻坐标。当前样本过滤前后均为 125 组、5 只霜狼；统计不混入新增剧情巡逻，不能拿这个有限样本代表整个世界。

CI 生产预览冒烟升级为 `early_route_e2e.py --snow`（新档完整前三章真实输入），再串行运行生命周期、混合指引、Q 跟踪、任务交付、离线版。总时限 25 分钟，长路线自身预算 900 秒；不带 --snow 的短路线仍为 300 秒。没有并行运行多个 Chromium，以降低内存竞争。脚本显式报告是否使用夹具，不混淆实走与任务逻辑回归。
