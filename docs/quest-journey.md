# 任务探索闭环：一次批次完成三个里程碑

## 目标

接支线 → 选取追踪目标 → 找到交付 NPC → 可靠保存。不要求每个小点都由使用者再次发送“继续”。每个阶段验证后提交和推送，并保留远端 Git 备份标签。

## 阶段 1：选择并保存追踪任务

提交 `2301df1`，已推送。

- Q 日志按主线/支线/隐藏和章节稳定排序，每页 3 项，数字键 1–3 或点击追踪，B/N 翻页。
- 当前追踪可选择支线，不再固定为主线。
- 新增可选 trackedQuestId，仍为存档版本 1，旧存档不含此字段也能读取。
- 目标完成、失败或消失时回退到可追踪的活动任务；交付目标始终在其他目标完成后优先引导。
- 卡片增加内部 identity，避免不同任务同名时缓存错误复用旧点击回调。
- 502 项单元测试、任务选择/刷新浏览器检查与构建通过。

## 阶段 2：真实目标指引和 NPC 状态

提交 `732adb4`，已推送。

- reach 导航到地点中心；talk 导航到已放置 NPC 的真实坐标，而非建筑中心或旧横队坐标。
- kill 指向已加载区域内最近的相关敌人刷新点；collect 可指向可能掉落所需物品的附近敌人，并明确不是必掉。
- 未发现目标时给来源提示，不编造远处物品/敌人的精确坐标。
- 修复东西/南北方向相等时仍强行多加一个方向的问题，显示八方位或“已到附近”。
- NPC 状态分为可接取 !、可交付 ?、进行中淡色点；附近名字和上下文提示反映状态，交付优先于新的任务发布。
- 区域声望限制只对既有 reach 规则给提示，本轮没有扩大到所有 NPC 互动，避免未经验证引入剧情死锁。
- 509 项单元测试、任务追踪和 NPC 布局浏览器回归与构建通过。

## 阶段 3：交付可靠性、完整详情与自动检查

- NPC 接取任务后、完成对话交付后立即保存；不再要求手动 K 才能保留任务变化。
- 保存前规范化追踪目标，已完成任务不继续留作已保存的追踪目标。
- 保存失败继续使用独立警告，不被“接取/完成成功”提示覆盖；K 重试仅保存，不重复发奖。
- 多任务发布提示限制展示长度并提示用 Q 查看，避免一次发布多项时塞满屏幕。
- V 打开任务详情，可分页查看全部目标与基础奖励，而不是只展示当前目标。详情模式数字键不意外改选追踪。
- 日志打开时数字键不会同时触发后台待选关键抉择；这不是所有模态交互的全面重写。
- 新增生产构建浏览器冒烟 CI：任务选择/刷新、NPC 接取/交付/存储异常与离线启动。固定 Playwright 版本，失败上传服务器日志。远端 CI 是否通过以 Actions 的实际结果为准，不拿本地通过代替。
