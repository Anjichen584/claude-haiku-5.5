# 地牢检查点与存档恢复（第四轮）

2026-10-14，基于第三轮 `d2aa0b5`。研读来源与取舍见 [开源项目学习记录](open-source-study.md)。

## 新规则

- 地牢每次移动和房间互动后自动存档；K 或底部按钮可手动保存/重试。
- 保存实际生成的房间图、当前位置、清理/领奖标记、Boss 状态、种子与各已进入楼层的档案。不在加载时重新生成旧地图。
- 标题“继续”显示活动地牢层数，直接回到保存的地牢位置。
- L 主动离开保留该层进度，再从入口传送门进入时恢复当前可进入层；不会重置宝箱、事件和休息点的领取标记。
- 胜利结算时同时写入奖励、已清理标记和下一层解锁；关闭胜利面板前刷新也能恢复。
- 战败退回地表，保留已清理房间，下次从该层入口继续。已完成层的档案不会因解锁下一层而被删除。
- 最高第 12 层完成时正确显示全部通关，不再提示“下一层解锁第 12 层”。

## 战斗中断边界

出战前先保存完整检查点；战斗中的单位位置、剩余敌人血量、技能冷却和中途击杀奖励不持续写入存档。中途刷新会回到出战前的未清理房间，需要重新按 E 开战；不是逐帧战斗续传。

一旦胜负结算，则整体保存该结果。已结算房间的房间奖励不能再次发放。没有实现通用防作弊或防止玩家复制旧存档。

## 主备保存

- 主键仍为 `rift-chronicles-save-v1`，旧版本 1 存档继续兼容。
- 地牢字段是可选扩展，内部单独标注格式版本 1。
- 每次写入前先验证新检查点；将上一份合法主存档保存到 `rift-chronicles-save-v1-backup`，再写入新主档。
- 主档损坏/缺失/读取失败时，若备份有效，可从标题继续恢复，并提示“进度可能回退”。两份都损坏时不会假装没有存档而静默开新游戏。
- 恢复的是完整角色+世界+地牢检查点，不把旧房间领取记录与新金币/物品拼接。
- 写入失败返回 false。地牢显示明确警告；保存失败时不进入战斗、不离开地牢；战斗返回会重试保存。商店也提示购买/出售尚未写盘。
- 主备存档仍在同一个浏览器来源下，**不是异地备份**。清除站点数据、浏览器卸载等会同时删除两份。

## 修复

- 删除独立的全局 run 缓存，活动地牢由当前角色会话持有，防止新游戏串入旧角色探索。
- `markCleared` 变为可检查的一次性领取操作，重复领奖返回 false。
- 修复战斗在帧开始已死亡时提前返回、不进入失败结算的边界。
- 房间快捷编号改为角标，减少与上下相邻房间标签重叠；编号也能点击移动。

## 验证

- 新增 `dungeon-checkpoint.test.ts` **64 个测试**：12 层图往返、深拷贝、归档与撤退、新角色隔离、27 类坏数据、主备恢复与读取/配额异常、完整检查点一致性。
- 全套 **453 个测试 / 36 个测试文件**。
- 浏览器 `dungeon_checkpoint_e2e.py`：真实传送门、按图相邻移动、开箱/休息后刷新与重复互动、退出再入、战斗中断回滚、真实普攻击杀后立即刷新、Boss/解锁/跨层归档、故意损坏主档后的备份恢复、存储配额异常时阻止出战/离开及手动重试、新角色隔离及战败后继续。
- 浏览器脚本注入传送门位置、部分战斗目标血量/位置、未保存的中途状态及故意死亡等夹具，明确不冒充正常数值条件下通关。

## 仍有边界

当前传送门默认选择活动层或最新已解锁层，尚无自由选择历史楼层的界面；想拿完已完成层的剩余房间，应在离开该层前继续探索。尚无逐帧战斗续传、存档导入/导出、多存档槽或跨设备同步。

独立装备实例、剩余预留词条、普通资源条件下的平衡与完整人工剧情验收仍未完成。
