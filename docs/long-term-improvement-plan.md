# 长线改进目标与每轮验收

原则：优先可玩性和明确缺陷；先定本轮目标，再修改、测试和推送。每轮保留存档兼容，不把“数量达标”等同于体验达标；不以未经测量的性能数字或脚本注入任务事件冒充真实完整通关。

## 已有基础（上一轮）

完成面板对象复用、任务进度恢复、地表保存失败提示、工具链升级与分支 CI，见 optimization-implementation.md。

## 第 1 阶段：NPC 与聚落布局（本轮已实施）

目标：人物不堆叠、交互不串人、标签可读、旧档仍能找到 NPC。

- [x] 提取独立、确定性的 NPC 放置模块。116 名 NPC 坐标与 JSON 输入顺序无关；同地点分布在建筑周围，不再每 2 格横向排队。
- [x] 人物之间至少 6 格（96 像素），大于两个 2.5 格交互圆半径之和；人物贴图宽 45 像素。
- [x] 避让所有地点中心建筑，以及出生点建筑、行旅商人、出生装饰守卫和裂隙入口的保留区。
- [x] 一份坐标驱动人物、最近交互选择、标签和 talk 导航目标。最近目标平距时按 id 稳定选择。
- [x] 仅显示附近名字，优先当前交互目标，标签矩形互相避让；选中对象显示脚下高亮。对话/面板打开时隐藏名字与高亮。
- [x] NPC 和地点中心周围保留 5 格空间，不生成装饰和敌人刷新点；怪物 key 不变。不会把全区域设成安全区。
- [x] 不修改地点坐标、NPC/任务 ID 或存档版本，重进场景会重新计算同一布局。
- [x] 数据/类型、475 项单元测试、生产与离线单文件构建通过。
- [x] 浏览器验证全部 116 名 NPC 坐标处可选中自身；守望队长真实 E 接取/对话、附近名字不重叠、存档刷新后位置一致，无 pageerror。
- [x] 商店、上一轮 UI/保存失败回归、file:// 单文件启动通过。
- [x] 24 章主线脚本通过；该脚本使用任务事件/背包注入辅助，验证的是任务串联与结局，不是 80 小时真实战斗通关。

边界：暂未设计每个聚落的专属房屋、职业工作点或 NPC 日程；地点名称、敌人名称与 NPC 标签之间的全局避让未全部覆盖；原有 40 个地点仍使用原坐标生成规则。名字有重复的剧情数据也未在本轮贸然合并或改名。

## 第 2 阶段：任务追踪与探索节奏（下一轮优先）

目标：玩家能知道做什么、去哪找谁，不依赖开发者瞬移。

- 审查第一小时的出生点→打狼→营地→关键 NPC 路线，区分“能脚本完成”与“正常游玩可理解”。
- 支线可追踪，reach/talk/collect/kill 目标各有合理指引；避免只显示主线导致接了支线却找不到人。
- NPC 可接取/可交付状态提示，明确接任务与进入对话的操作差异。
- 检查区域门槛是否真正约束相关互动，而不只是 reach 标记；避免新增剧情绕过。
- 验收：真实按键完成一条早期任务链和一条 NPC 支线，刷新不丢追踪目标、不重复发奖。

## 第 3 阶段：聚落与场景可读性

- 根据职业设置少量有意义的工作区与地标；修复 NPC、地点、敌人标签和 HUD 遮挡。
- 审查重复 NPC 显示名、台词说话人和任务发布身份，先建立映射再改数据。
- 评估地点密度和区域锚点，不直接整体重排破坏已有路线和旧档。
- 验收：出生营地及至少两个不同区域聚落的视觉/互动检查。

## 第 4 阶段：战斗与成长闭环

- 检查前期伤害、受击反馈、技能收益、补给成本与战败代价。
- 明确装备实例/词条未实现部分，避免把预留属性显示为已生效。
- 对正常路线而非测试房间做奖励与资源消耗采样。
- 验收：可重复的早中期战斗场景、成长与补给回归；不在无数据时宣称全局平衡。

## 第 5 阶段：架构、性能、发布

- 分批抽离 OverworldScene 的 UI、交互与导航职责，不一次性重写。
- 面板内容计算限频/脏标记；测量区块生成卡顿与长存档成本。
- 浏览器冒烟接入 CI，保留离线无网络与地牢检查点回归。
- 合并前核对远端 main 变化，避免覆盖他人提交；推送独立分支不等于已更新 Pages。

## 每轮交付标准

1. 写明本轮目标和不做的范围。
2. 修复代码与必要数据，添加能复现问题的测试。
3. 类型、数据、单元测试、构建通过；涉及交互时运行浏览器检查。
4. 记录实际执行的结果与未验证部分。
5. 提交并推送分支，提供提交号与后续目标，不直接覆盖默认分支。
