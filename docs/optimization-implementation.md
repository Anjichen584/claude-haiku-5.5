# 可靠性与界面优化实施记录

本轮在独立分支 `optimize/reliability-and-ui` 实施，默认分支不直接修改。

## 修改

- CardPanel 按显示内容签名复用对象；技能装配栏按槽位和选择复用，避免相同内容每帧销毁/重建。隐藏再打开面板会正确失效。仍会计算面板内容，未宣称已完成全部 UI 性能优化。
- 已知任务恢复时按当前目标定义补齐/截断进度并限制目标上限，兼容旧档；已完成任务不重新发奖。拒绝无效任务事件数量。迁移后达到上限的 active 任务在匹配事件到来时结算一次。
- 地表保存统一入口同步坐标/时间并显示独立失败警告；成功重试后清除，不被操作成功提示覆盖。此变更覆盖地表场景调用，不代表全项目所有存储调用都已重构。
- Vite 升级至 8.3.4，Vitest 升级至 4.1.11，并更新锁文件及 Node 引擎要求。
- 默认开发/预览配置绑定本机；`SANDBOX_PREVIEW=1` 才绑定 0.0.0.0，并额外放行 `.e2b.app`，不再允许任意 Host。命令行显式 --host 仍可覆盖绑定。
- 新增独立分支与 PR CI，覆盖类型、内容数据、单元测试、单文件构建和高等级依赖审计。CI 未包含浏览器测试，下面浏览器结果为本地执行。

## 验证结果

- 类型检查、内容数据校验：通过。
- Vitest：37 个文件、465 项测试通过（原 453 项，新增 12 项）。
- 生产构建和单文件构建：通过。
- npm audit：0 个已知漏洞（包含开发依赖；审计结果随公告数据库变化）。
- 浏览器 Playwright Chromium：
  - `skill_e2e.py`：学习、金币不足限制、重置返还通过。
  - `shop_e2e.py`：交易、余额不足、关闭后移动通过。
  - `standalone_e2e.py`：file:// 打开并开始游戏，无外部网络请求。
  - `optimization_e2e.py`（新增）：静止面板保持相同卡片/槽位对象；模拟配额错误提示、恢复存储后手动重试通过。
  - `dungeon_checkpoint_e2e.py`：房间奖励、休息、刷新/重进、战斗回滚、Boss 结算/层数、备份恢复、保存失败阻断、角色隔离与战败保留通过。

- 构建输出入口 JS：1,756.49 kB，gzip 475.22 kB；原为 1,902.72 / 497.96 kB。工具链变更导致体积差异，不等价于实际帧率提高。

## 边界

没有进行完整长线游玩、全剧情通读或低端设备性能基准；没有一次性拆分全部大场景。后续可继续抽离场景职责、降低内容计算频率、补充内容深只读约束及浏览器 CI。当前修改不修改发布分支，需合并到 main 后现有 Pages 工作流才会发布。
