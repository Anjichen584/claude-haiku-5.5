# 综合优化审查（先审查，后修改）

## P1：面板每帧销毁并重建

证据：`src/scenes/OverworldScene.ts:406–410` 在 update 中对已打开面板调用 refresh；例如 `refreshSkillPanel` 调用 `renderCards`，后者调用 `CardPanel.show`。`src/ui/CardPanel.ts` 中 show 每次先 `root.removeAll(true)`，再创建文字、图形、卡片与交互监听；技能面板还重建装配栏。

影响：内容未变也重复分配、绘制文本与销毁对象，可能增加 CPU/GC 开销；悬停反馈也可能被持续重建打断。需要浏览器测量确认具体帧率与交互影响。

建议：引入数据脏标记/版本号，仅在打开、翻页、装备/背包/声望/技能变化时更新；冷却或时间显示单独限频。保留卡片对象并更新文本和样式，而不是全部销毁。验收：无状态变化时连续多帧不重建，键盘/点击/翻页正常，采样比较面板打开前后耗时。

## P1：存档接受不完整的任务进度

证据：`src/state/session.ts` 的 parseSave 检查 progress 是非负整数数组，却未按任务定义验证长度和目标上限。`src/narrative/QuestManager.ts` 构造函数仅补缺失任务；report 直接计算 `progress[i] + amount`。

影响：已知任务若存为 active 且 progress=[]，结构校验可通过，但事件累计使用 undefined，产生 NaN，任务无法正常完成；后续 JSON 序列化为 null，又会被存档校验拒绝。此结论来自静态路径，尚未新增可执行复现测试。

建议：解析/恢复阶段对已知任务按定义验证或迁移目标数组，明确未知任务和内容版本升级策略；不应简单把所有旧档一律拒绝。补 active 空数组、缺项、超长、超限和目标定义变化的回归用例。

## P1：开发工具链安全与网络暴露

证据：审计报告指向 Vite、Vitest、esbuild、tinypool、vite-node、@vitest/mocker。Vite 配置绑定 0.0.0.0 且 allowedHosts=true；允许所有主机名是为沙箱预览服务，但不适合作为所有环境的默认策略。

影响范围：主要为开发/测试环境，并不等价于静态发布页面存在相同漏洞。例如 Vitest UI 告警依赖 UI 服务运行，当前 npm test 使用 vitest run，未开启 UI。tinypool 告警的利用条件也不能仅凭依赖存在判定。

建议：在独立提交中升级兼容的 Vite/Vitest 与锁文件，核对 Node 引擎和单文件构建兼容性；不要直接执行未经验证的 audit fix --force。开发默认本机绑定，沙箱模式通过显式环境配置绑定 0.0.0.0 并放行受控预览域名。升级后重新运行全部检查和审计。

## P2：多处自动保存忽略失败

证据：`OverworldScene.ts` 的手动 saveGame 会检查 persistSession 返回值；learnSkill、装备操作和使用药剂等多处直接调用 persistSession 而不处理 false。`saveRepository.ts` 已具备捕获存储异常的基础设施，这是优点。

影响：操作在内存中成功，但存储拒绝/配额不足时玩家可能不知道进度未落盘。自动保存每次还涉及完整快照、排序、序列化、校验以及主备写入；长线存档的实际延迟需采样。

建议：集中保存入口与错误提示，区分内存状态成功和落盘成功；高频非关键保存合并，关键场景切换保持可靠写入。验证存储禁用、配额满、主档损坏与备份恢复；保留现有地牢检查点语义，不盲目改为延时保存。

## P2：只读数据保证为浅层

证据：`src/data/loader.ts` 使用 Object.freeze 包住 GameData 外层；数组与内部定义仍可变，Readonly<GameData> 也不使嵌套结构只读。

影响：与“全部冻结、运行时只读”的注释不一致，意外修改可能污染跨场景缓存。目前未发现具体污染事故。

建议：先强化 readonly 类型；开发模式深冻结以暴露误写，按实际启动开销决定生产是否深冻结。

## P2：发布门禁不覆盖独立分支/PR

证据：`.github/workflows/pages.yml` 仅 main push 和 workflow_dispatch；类型、数据、测试检查与部署在一个任务内。审查分支推送不会自动触发这些门禁。仓库存在 scripts/e2e，但当前工作流不运行。

建议：独立 CI 覆盖 PR/分支，最低 permissions=contents:read；部署任务才授予写权限。先接入标题进入游戏、地牢恢复、商店、单文件启动等稳定冒烟用例。Action 固定完整提交 SHA 可另做供应链加固。

## P3：可维护性与包体

`OverworldScene.ts` 1175 行、`TestRoomScene.ts` 521 行，输入、叙事、面板、渲染、存档职责混合。建议按域逐步抽离面板控制器、保存协调器、地表流式加载，保留既有纯逻辑模块与测试优势，不做一次性重写。

生产入口约 1.90 MB 包含 Phaser 和内容数据，不能仅靠大小认定性能差。先测低端设备启动、文本渲染和内存，再决定裁剪/分包。现有单文件脚本只内联入口 JS，任何分包、外部 CSS 或动态 import 优化都必须同步升级打包器，否则会破坏离线单文件目标。
