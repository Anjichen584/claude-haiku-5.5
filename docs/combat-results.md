# 战斗第三轮：清晰结算、确认保护与保存重试

## 本轮目标

改善战斗结束后的可读性与可靠性，不更改伤害、奖励数值、任务规则或存档格式。

## 修改

- 提取纯逻辑的战前快照、战后差额汇总与分页函数。汇总来自已结算的会话状态，而不是解析日志或再次发奖励。
- 新增固定尺寸的结算面板：胜负、击败数量、模拟战斗用时、经验/金币差额、等级变化、返回生命/魔力，以及物品、声望、稳定度、技能点与任务完成详情。
- 物品明确标记“背包净变化”：掉落与消耗相抵时显示净额，不能把它解释成独立掉落清单。经验/金币差额包含击杀、地牢房间和本场任务结算，不是只统计击杀。
- 详情每页 6 条，N/P 或点击翻页；不再只保留前 8 条战利品日志。
- 结算显示后至少等待 450 ms，并等待松开 Space；清除此前缓冲的闪避输入，随后新按 Space 或点击才返回。避免最后一次闪避误关结算。
- 保存状态直接显示在结算面板上。R/点击可重试保存，Space/返回按钮也会重试。保存失败留在当前界面，不会重新调用奖励结算；成功后更新“已保存”。
- `finished` 的一次性结算保护保留，保存与翻页均为独立操作，不发放奖励。

## 验证

- 41 个测试文件、496 项单元测试通过（新增 6 项）。覆盖实际差额、重复物品与消耗、只读汇总、净零变化、完整分页和结算确认保护。
- 类型检查、数据校验、生产及离线单文件构建通过；完整 npm audit 0 个已知告警。
- 新增 `combat_results_e2e.py`：夹具注入多种物品变化并通过真实伤害回调结束战斗，真实按键/点击验证翻页、按住 Space 不误关、配额错误警告、R 重试、不重复发奖、返回和刷新恢复。这个用例不是无注入实战。
- `combat_engagement_e2e.py`：真实输入追击、释放停止、手动覆盖、闪避、技能转向和胜利返回通过；新增等待明确的结算确认就绪状态。
- `combat_targeting_e2e.py`、`combat_skills_e2e.py`：锁定、群怪位置校正、预警固定、技能和连招、胜利刷新等回归通过。
- `dungeon_checkpoint_e2e.py`：地牢结算、Boss 推进、战败保留、刷新回滚、主备档恢复和存储异常等回归通过。
- `standalone_e2e.py`：file:// 新游戏可启动且无外部网络请求。
- 上述浏览器检查无 pageerror；已检查结算面板截图和详情/保存状态边界。

## 边界

保留现有战败结算行为：已发放的击杀收益和已结算任务状态仍按原规则保留；本轮不是战败惩罚重设计。用时来自模拟战斗时钟，不是浏览器后台墙钟计时。不包含无缝地表战斗、完整平衡或长线游玩验收。

下一轮优先返回探索任务体验：支线追踪、目标地点/交付 NPC 指路与可接取/可交付状态，避免只优化战斗却仍然不知道任务该去哪。
